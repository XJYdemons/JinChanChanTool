# PR 描述模板（JinChanChanTool 二次开发贡献）

> 使用方法：复制下方模板到 PR 描述框，按实际改动填写；每个 PR 只包含一类改动（数据更新 / Bug 修复 / 新功能），标题格式：`[类型] 简要描述`

---

## 模板一：数据更新类（英雄/装备/阵容/推荐数据）

### 标题示例
`[数据更新] S16 装备数据与图标资源同步更新`

### 描述

**概述**
同步更新 xxx 赛季的英雄/装备/阵容数据，与当前游戏版本保持一致。

**改动内容**
- [ ] 英雄数据：新增/修改英雄 N 个（HeroData.json）
- [ ] 装备数据：新增/修改装备 N 个、合成路径调整（Equipment.json）
- [ ] 装备图标：新增/更新图片资源 N 张（EquipmentImages/）
- [ ] 阵容模板/推荐阵容更新（LineUps.json / RecommendedLineUps.json）

**数据来源**
- 数据依据：□ 游戏内实测截图 □ 官方公告 □ 大数据网站（metatft 等）
- 核对方式：英雄名称/费用/职业/羁绊已逐条核对；装备合成路径与游戏内一致

**测试情况**
- [ ] 程序内切换赛季正常加载，无格式错误提示
- [ ] 英雄选择面板/阵容面板显示正常，图片映射无缺失
- [ ] 装备推荐功能正常展示新装备

**影响范围**
- 仅影响 xxx 赛季数据文件，不涉及程序逻辑；同名英雄合并、按费用排序等既有规则不变

## 模板二：Bug 修复类

### 标题示例
`[修复] 修复模拟器环境下程序误操控游戏窗口外界面问题`

### 描述

**问题描述**
在 MuMu/雷电模拟器环境下，程序自动操作时会误点击到游戏窗口以外的区域（如模拟器工具栏/其他应用），导致异常操作。

**复现步骤**
1. 开启 xxx 功能
2. 模拟器窗口非最大化/窗口位置变化时
3. 观察到鼠标点击落在窗口外区域

**根因分析**
程序使用模拟器主窗口矩形作为操作范围，而主窗口包含工具栏等非游戏画面区域；且程序点击未与用户操作区分（MouseHook 无法识别程序点击）。

**修复方案**
- 操作范围改为游戏渲染子窗口（枚举子窗口取最大可见区域，自动适配窗口移动/缩放）
- 程序点击增加标记机制（`IncrementProgramClickCount`/`DecrementProgramClickCount`），与用户手动操作区分，避免争夺光标控制权
- 未找到目标窗口时安全跳过，不做任何点击

**测试情况**
- [ ] 模拟器（MuMu 1600×910 / 雷电 1600×900）窗口移动、缩放后坐标仍准确
- [ ] 多显示器/不同 DPI 环境验证通过
- [ ] 程序点击不再干扰用户手动操作

**影响范围**
- 涉及文件：`Services/CardService.cs`、`Tools/MouseTools/MouseControlTool.cs` 等
- 兼容性：不改变现有功能行为，仅修正操作范围

## 模板三：新功能类

### 标题示例
`[功能] 新增自动拾取棋盘物品（手动触发）`

### 描述

**功能简介**
新增「拾取物品」按钮：点击后对棋盘预设坐标依次执行一轮盲点右键点击，利用英雄移动路径自动拾取掉落物（装备/法球），解放手动逐点拾取操作。

**设计要点**
- 坐标基于项目现有锚点模板体系（1600×910 基准 + 底部居中锚点），经坐标计算服务缩放，适配任意窗口位置/分辨率
- 点击复用程序点击标记机制，不干扰用户操作检测；点间间隔 1.1s 防连点
- 未绑定游戏窗口时点击按钮不动作（安全保护）

**使用方式**
主窗口功能区点击「拾取物品」按钮即可触发一轮拾取（5 个棋盘坐标点）。

**测试情况**
- [ ] 模拟器环境实测：触发一轮拾取，掉落物可被拾取
- [ ] 未绑定窗口时按钮无副作用
- [ ] 与其他功能（自动拿牌/刷新）并行无冲突

**注意事项**
- 若考虑自动化操作风险（对局内自动点击），可评估后再决定是否合并；本功能为手动触发式，非持续自动化

## 通用检查清单（提交前自查）

- [ ] fork 仓库已同步上游最新代码
- [ ] 仅在独立分支上改动，PR 只包含本次目标文件
- [ ] Commit 信息清晰（`[类型] 描述`），必要时拆分多个 commit
- [ ] 本地编译通过（Release x64），无新增警告/错误
- [ ] 数据类改动注明来源；代码类改动附测试说明
- [ ] 已通过 QQ 群/Issue 与作者沟通（新功能/大改动建议先沟通）
